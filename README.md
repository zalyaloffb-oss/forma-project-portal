# Форма — каталог проектов

Рабочий сайт: https://zalyaloffb-oss.github.io/forma-project-portal/

Код каталога и небольшие превью размещены на GitHub Pages. Материалы проектов
читаются с Яндекс Диска; Beget не используется.
Модели открываются по отдельным ссылкам с названием проекта, например `/pervyy-trest/`.
3D открывается отдельной страницей в той же вкладке, без вложенного окна каталога.
Кнопка закрытия просмотрщика возвращает в каталог.
Сохранены структура, изоляция, маркировка, сечения, замеры, узлы вращения,
перемещение деталей, история действий и экспорт выбранной детали в DXF.

## Данные

Левая панель открывается шестерёнкой. В ней доступны «Стенды», «Мебель» с
подразделами и «Архив». Для прежних записей раздел определяется по названию и
папке Fusion; выбор раздела в редакторе имеет приоритет. Архив назначается только
флажком «В архиве»: такие проекты скрываются из остальных разделов. Снятие флажка
возвращает проект в его раздел. Эти изменения сохраняются как локальные черновики
и публикуются через обычный экспорт из настроек и `tools/import_drafts.py`.
Для быстрого переноса нажмите значок папки со стрелкой на карточке или
«Переместить в раздел» в открытом проекте, выберите назначение и нажмите
«Переместить». Перенос в архив сохраняет прежний раздел; для возврата выберите
нужный раздел в том же окне.

Каталог загружает PDF-движок только при открытии или импорте PDF. Публичные
обложки отображаются обычными ленивыми изображениями; локальные обложки и файлы
черновиков остаются в браузере. PDF.js использует отдельный worker и штатный fallback.

Для каждой модели подготовлена точная gzip-копия `modelGzipUrl`. Просмотрщик
распаковывает её встроенными средствами браузера; при неподдерживаемом декодере,
ошибке запроса или повреждении используется исходный GLB. Геометрия, маркировка
и идентификаторы не упрощаются. Публикация из Fusion/Max создаёт такую копию
автоматически. Для уже опубликованных моделей: `python tools/prepare_model_transports.py`.

Проверки: `python tests/test_performance.py`, `node tests/test-model-transport.mjs`.
Размер стартовых модулей: `python tools/audit_payload.py` (это исходные байты,
а не браузерные тайминги или оценка Lighthouse). Старые версии файлов сохранены,
поэтому размер репозитория не равен объёму одной загрузки страницы.

### Тест загрузки с Яндекс Диска

Просмотрщик принимает `?yadisk=<публичная HTTPS-ссылка на GLB>`.
Пример для тачпанели: `/tachpanel/?yadisk=https%3A%2F%2Fdisk.yandex.ru%2Fd%2FyT0IjZsMeXBZqg`.
Это отдельный тест публичной ссылки. Обычные ссылки каталога используют папку
Диска, заданную в `data/asset-storage.json`, без дополнительных параметров.
Кнопка копирования ссылки сохраняет выбранный источник.

Для теста нужен публичный файл GLB до 200 МБ со встроенными геометрией и текстурами,
с разрешённым скачиванием. Временная ссылка скачивания запрашивается заново при
каждом открытии. OAuth, куки и ключи доступа не используются. `no-referrer` обязателен:
downloader Яндекса отвечает HTTP 403 на запрос с Referer сторонней страницы.
Проверяются размер, формат и SHA-256 из метаданных Диска. При отказе сервиса
показывается ошибка без подмены файлом GitHub. Это не проверка доступности для всех
провайдеров; ограничения публичных скачиваний Диска сохраняются.

Проверка загрузчика: `node tests/test-yandex-model.mjs`.

### Прямые загрузки владельца на Диск

`tools/yandex_disk.py` — локальный API/MCP-коннектор без сторонних библиотек.
Одноразовая команда `setup` открывает локальную форму приёма OAuth-токена.
Токен проверяется через API и хранится в Windows DPAPI под текущей учётной записью,
в `%LOCALAPPDATA%/EES/YandexDisk/oauth.dpapi`, с закрытыми правами папки.
В репозиторий, браузерный код и конфигурацию MCP токен не помещается.

Команды: `info`, `mkdir <путь>`, `stat <путь>`, `upload <путь> --file <локальный файл>`,
`publish <путь>`, `mcp`. Все пути назначения ограничены папкой
`EES проекты/forma-project-portal`. Замена отличающегося файла требует `--overwrite`.
MCP допускает исходные файлы только из папок, перечисленных в закрытом локальном
`allowed-roots.json`. Коннектор не предоставляет команд удаления.

`tools/migrate_yandex.py --manifest <файл.json>` составляет список текущего Git-коммита.
Флаг `--upload` запускает перенос максимум в четыре потока, с проверкой размера и SHA-256
на стороне Диска. Используются точные байты Git, включая исходные окончания строк;
неопубликованные и неотслеживаемые файлы не загружаются. Повторный запуск проверяет
уже переданные файлы и продолжает перенос. Список и отчёт храните вне репозитория.

### Материалы на Яндекс Диске

Папка проекта: https://disk.yandex.ru/d/H3GdhvzxSwQWsA.
На Диск скопировано всё содержимое опубликованного Git-дерева, с проверкой
размера и SHA-256 каждого файла. История Git и закрытые локальные настройки
в перенос не входят. `data/asset-storage.json` связывает прежние адреса `assets/`
с проверенными файлами в этой папке. Короткие ссылки моделей и данные проектов сохранены.

`asset-store.js` получает свежий адрес скачивания через публичный API,
скачивает без Referer/куки и сверяет размер и SHA-256. При отказе Диска
показывается ошибка. Старые прямые адреса файлов обрабатывает `404.html`.
Сайт не содержит OAuth-токенов. Для открытия посетителю не нужен аккаунт Яндекса.
Социальные превью и несколько небольших файлов для тестов остаются на Pages.
Удаление материалов из текущей ветки не очищает прежнюю историю Git.

Новые публикации через `write_asset` отправляют модели, gzip, PDF и исходники
сразу на Диск и добавляют запись только после проверки обоих файлов.
Обложки сохраняются на Pages. Если загрузка не удалась, новая ссылка не публикуется.
Проверки: `node tests/test-asset-store.mjs`, `python tests/test_cloud_publication.py`.

Публичный список — `data/catalog.json`; логические адреса материалов — `assets/`.
Перенос 04.11.2026 выполнен из доступных локальных копий: Beget не отвечал по HTTP и SSH.
Восстановлены семь проектов. «Первый трест» дополнительно обновлён из открытой
Fusion v183 по прямому подтверждению пользователя:1546 реальных тел, включая
6 деталей цоколя ресепшена. Восемь пустых записей без граней и вершин не
экспортируются; исходный CAD не менялся. Прежние PDF сохранены, не перегенерированы. Последние изменения, которые остались только на недоступном сервере,
нужно сверить с его базой после восстановления доступа. Не выдавайте локальную
копию за полный актуальный дамп MySQL.

## Правки через сайт

Добавление проектов, PDF/JPG и менеджеров сохраняет локальные черновики в браузере.
Они не становятся общими автоматически. В настройках есть кнопка
«Скачать изменения для публикации». Владелец импортирует пакет:

```powershell
python tools/import_drafts.py путь-к-файлу.json
python tools/validate_site.py
git add data assets */index.html
git commit -m "Update catalogue drafts"
git push origin main
```

После публикации перенесённые черновики можно очистить только после проверки файлов.
До этого не очищайте хранилище браузера: оно содержит ещё не опубликованные файлы.
GitHub Pages не выполняет PHP/MySQL; серверная авторизация, серверная генерация PDF
и прежняя форма загрузки в Beget в этой версии не используются.
Готовые монтажные PDF доступны, а Max-экспортёр может создать PDF перед публикацией.

## Баннеры 3D

Во вкладке «Баннеры 3D» открывается текущая модель проекта по той же короткой
ссылке с `?view=banners`. Плоские поверхности выбираются щелчком. Кнопка
«Болванка» скрывает конструкцию и оставляет только выбранные поверхности.
Для баннера поверх нескольких коробов включите «Прямоугольная болванка»,
укажите ширину, высоту и сдвиг в миллиметрах. Это визуальная схема, без припусков.
Каждая поверхность принимает JPG/PNG, поворот и отражение. По названиям
выбираются только явно обозначенные тела баннеров; результат нужно проверить.

Схема с текстурами сохраняется отдельно в IndexedDB устройства либо в JSON.
«Скачать болванку GLB» экспортирует только плоскости в метрах со встроенными текстурами.
Схема привязана к проекту, предмету и URL версии модели; после замены модели
нельзя применять старые индексы граней. JSON можно загрузить обратно.
Ссылка показывает опубликованную модель, но не передаёт локальные текстуры.
Новые текстуры не отправляются на сервер автоматически.

## Публикация из Fusion и Max

На компьютере владельца используется адаптер `tools/GitHubPublisher.py`.
Он читает только путь к репозиторию из локальной настройки
`~/.codex/secrets/forma-github/connection.json` и вызывает Git.
Аутентификацией управляет Git Credential Manager; ключей и токенов в сайте нет.
Общий алгоритм находится в `tools/publish_export.py`: обновление по идентификатору
исходника/проекта, затем по уникальному названию, иначе создание нового проекта.
Метаданные и документы сохраняются, короткая ссылка не меняется.

Дата создания берётся из `dateCreated` первой сохранённой версии Fusion,
а не из последней версии или часов экспортёра. В карточке используется календарная
дата Москвы; исходный UTC timestamp и происхождение сохраняются в метаданных.
Если Fusion не вернул дату, публикация сообщает об ошибке и не подставляет сегодняшнюю.
Экспортёр владельца использует `FusionMetadata.py` рядом со своим основным модулем.
Сеточные тела также сохраняют названия и пути экземпляров. `FusionMeshMetadata.py`
читает вершины в координатах сборки и исходные цвета для объектов, у которых USD
не сохранил привязку материала. Повторяющиеся компоненты остаются отдельными экземплярами.

Крупные исходники F3D свыше 200 МБ загружаются потоково и скачиваются напрямую,
без чтения всего архива в память браузера. Верхняя граница исходника — 50 ГиБ,
проверенный лимит текущего Диска. Для отображаемого GLB сохраняется лимит 200 МБ.

Пакетный импорт из папки запускается внутри Fusion через `tools/fusion_batch.py`;
каждая папка/модель обрабатывается отдельным событием без сохранения CAD.
Прогресс и готовые манифесты находятся в указанной папке вывода (`job.json`).
`tools/publish_fusion_batch.py --job <путь/job.json>` проверяет и загружает готовые
экспорты на Диск, сохраняя документы и идентификаторы существующих проектов.
Файл `stop.request` в папке задания останавливает обе части на ближайшем этапе.
`pause-publication.request` временно приостанавливает только публикацию между
моделями, чтобы проверить и зафиксировать согласованный пакет в Git.
Ошибки и пустые модели перечисляются отдельно; незавершённый импорт можно продолжить.

Публикация возвращает подтверждение отправки Git-коммита. Сборка GitHub Pages
после него занимает дополнительное время; проверьте Actions перед сообщением,
что новая модель уже доступна посетителям.

Существующие экспортёры Beget сохранены локально для восстановления старого хостинга.
При включённом Диске материалы до 200 MiB загружаются через коннектор.
Крупные исходники F3D/MAX передаются потоком с проверкой SHA-256 (проверенный
предел аккаунта 50 GiB); для них используется прямая ссылка скачивания.
В память просмотрщика такие исходники не загружаются. Предел GLB остаётся 200 MiB.
Без облачного хранилища сохраняется прежний предел репозитория 99 MiB.

## Проверка

```powershell
python tools/validate_site.py
node tests/test-routing.mjs
```

Служебный `tools/migrate_local.py` — разовый восстановитель из копий владельца;
он не является ежедневной командой обновления и не должен перезаписывать
каталог после новых публикаций. Для обычного обновления используйте publisher.

## Мебель внутри проекта

В карточке «Первый трест» вкладка «Мебель» содержит кашпо Fusion v17 (27 деталей).
Прямая ссылка: https://zalyaloffb-oss.github.io/forma-project-portal/pervyy-trest/kashpo/.
Предметы хранятся в `project.furniture` со своими моделями, обложками и исходниками.
Повторный экспорт того же Fusion DataFile обновляет этот предмет внутри проекта; модель стенда и документы сохраняются.
