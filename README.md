# Форма — каталог проектов

Рабочий сайт: https://zalyaloffb-oss.github.io/forma-project-portal/

Каталог и файлы размещены на GitHub Pages и не обращаются к Beget.
Модели открываются по отдельным ссылкам с названием проекта, например `/pervyy-trest/`.
3D открывается отдельной страницей в той же вкладке, без вложенного окна каталога.
Кнопка закрытия просмотрщика возвращает в каталог.
Сохранены структура, изоляция, маркировка, сечения, замеры, узлы вращения,
перемещение деталей, история действий и экспорт выбранной детали в DXF.

## Данные

Каталог загружает PDF-движок только при открытии или импорте PDF. Публичные
обложки отображаются обычными ленивыми изображениями; локальные обложки и файлы
черновиков остаются в браузере. PDF.js использует отдельный worker и штатный fallback.

Для каждой модели подготовлена точная gzip-копия `modelGzipUrl`. Просмотрщик
распаковывает её встроенными средствами браузера; при неподдерживаемом декодере,
ошибке запроса или повреждении используется исходный GLB. Геометрия, маркировка
и идентификаторы не упрощаются. Публикация из Fusion/Max создаёт такую копию
автоматически. Для уже опубликованных моделей: `python tools/prepare_model_transports.py`.

Проверки: `python tests/test_performance.py`, `node tests/test-model-transport.mjs`.
Размер стартовых модулей: `python tools/audit_payload.py` (это исходные байты,
а не браузерные тайминги или оценка Lighthouse). Старые версии файлов сохранены,
поэтому размер репозитория не равен объёму одной загрузки страницы.

Публичный список — `data/catalog.json`; модели, PDF, обложки и доступные исходники — `assets/`.
Перенос 04.11.2026 выполнен из доступных локальных копий: Beget не отвечал по HTTP и SSH.
Восстановлены семь проектов. «Первый трест» дополнительно обновлён из открытой
Fusion v183 по прямому подтверждению пользователя:1546 реальных тел, включая
6 деталей цоколя ресепшена. Восемь пустых записей без граней и вершин не
экспортируются; исходный CAD не менялся. Прежние PDF сохранены, не перегенерированы. Последние изменения, которые остались только на недоступном сервере,
нужно сверить с его базой после восстановления доступа. Не выдавайте локальную
копию за полный актуальный дамп MySQL.

## Правки через сайт

Добавление проектов, PDF/JPG и менеджеров сохраняет локальные черновики в браузере.
Они не становятся общими автоматически. В настройках есть кнопка
«Скачать изменения для публикации». Владелец импортирует пакет:

```powershell
python tools/import_drafts.py путь-к-файлу.json
python tools/validate_site.py
git add data assets */index.html
git commit -m "Update catalogue drafts"
git push origin main
```

После публикации перенесённые черновики можно очистить только после проверки файлов.
До этого не очищайте хранилище браузера: оно содержит ещё не опубликованные файлы.
GitHub Pages не выполняет PHP/MySQL; серверная авторизация, серверная генерация PDF
и прежняя форма загрузки в Beget в этой версии не используются.
Готовые монтажные PDF доступны, а Max-экспортёр может создать PDF перед публикацией.

## Баннеры 3D

Во вкладке «Баннеры 3D» открывается текущая модель проекта по той же короткой
ссылке с `?view=banners`. Плоские поверхности выбираются щелчком. Кнопка
«Болванка» скрывает конструкцию и оставляет только выбранные поверхности.
Для баннера поверх нескольких коробов включите «Прямоугольная болванка»,
укажите ширину, высоту и сдвиг в миллиметрах. Это визуальная схема, без припусков.
Каждая поверхность принимает JPG/PNG, поворот и отражение. По названиям
выбираются только явно обозначенные тела баннеров; результат нужно проверить.

Схема с текстурами сохраняется отдельно в IndexedDB устройства либо в JSON.
«Скачать болванку GLB» экспортирует только плоскости в метрах со встроенными текстурами.
Схема привязана к проекту, предмету и URL версии модели; после замены модели
нельзя применять старые индексы граней. JSON можно загрузить обратно.
Ссылка показывает опубликованную модель, но не передаёт локальные текстуры.
Новые текстуры не отправляются на сервер автоматически.

## Публикация из Fusion и Max

На компьютере владельца используется адаптер `tools/GitHubPublisher.py`.
Он читает только путь к репозиторию из локальной настройки
`~/.codex/secrets/forma-github/connection.json` и вызывает Git.
Аутентификацией управляет Git Credential Manager; ключей и токенов в сайте нет.
Общий алгоритм находится в `tools/publish_export.py`: обновление по идентификатору
исходника/проекта, затем по уникальному названию, иначе создание нового проекта.
Метаданные и документы сохраняются, короткая ссылка не меняется.

Публикация возвращает подтверждение отправки Git-коммита. Сборка GitHub Pages
после него занимает дополнительное время; проверьте Actions перед сообщением,
что новая модель уже доступна посетителям.

Существующие экспортёры Beget сохранены локально для восстановления старого хостинга.
Файлы более 99 MiB не добавляются автоматически: для них нужно отдельное решение
с GitHub Releases, а не незаметное усечение файла или фиктивная ссылка.

## Проверка

```powershell
python tools/validate_site.py
node tests/test-routing.mjs
```

Служебный `tools/migrate_local.py` — разовый восстановитель из копий владельца;
он не является ежедневной командой обновления и не должен перезаписывать
каталог после новых публикаций. Для обычного обновления используйте publisher.

## Мебель внутри проекта

В карточке «Первый трест» вкладка «Мебель» содержит кашпо Fusion v17 (27 деталей).
Прямая ссылка: https://zalyaloffb-oss.github.io/forma-project-portal/pervyy-trest/kashpo/.
Предметы хранятся в `project.furniture` со своими моделями, обложками и исходниками.
Повторный экспорт того же Fusion DataFile обновляет этот предмет внутри проекта; модель стенда и документы сохраняются.
